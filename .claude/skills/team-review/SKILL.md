## 依頼

上の変更を、次の手順でレビューしてください。重点観点の指定: $ARGUMENTS

1. `git diff` と `git diff --cached` で差分全体を読む。差分だけで判断できない箇所は、関係するファイルを Read で開いて確認する。
2. 下の「チェック項目」に沿って問題を探す。推測ではなく、該当する行を示せるものだけを指摘する。
3. ファイルは編集しない。修正案はコード片として示すだけにする。

## チェック項目

- 正しさ: 条件分岐の抜け、null/undefined の扱い、非同期処理の await 漏れ、エラー時の挙動
- Next.js: Server Component と Client Component の境界（"use client" の付け過ぎ・付け忘れ）、サーバー専用の処理や秘密情報がクライアントに渡っていないか、`NEXT_PUBLIC_` 付きの環境変数に秘密情報を入れていないか
- セキュリティ: 入力値の検証、`dangerouslySetInnerHTML`、認可チェックの抜け、ログへの個人情報出力
- 型: `any` や型アサーション（`as`）で問題を隠していないか
- テスト: 振る舞いを変えたのにテストが追加・更新されていない箇所
- 読みやすさ: 命名、重複、1つの関数に詰め込みすぎていないか

## 出力形式
